# MANTA 节点退出研究：完整实验设计 v1.0

日期：2026-10-06。状态：设计稿；本文中的新实验规模与验收条件均为计划，不代表已经运行或通过。

**当日后续范围调整（优先于下文远期规模）：** 用户要求小规模迭代。当前只安排两个批次：一个自建交接 case × 五组 = 5 次后半段执行；六个 WorkBench case × 一遍 × 五组 = 30 次，当前合计 35 次。原 75 次 pilot、10–20 个 WorkBench 任务和 1,500 次正式测试均延后，属于方法稳定后的可选扩展。WorkBench 先记录原始领域/行号、数据文件与题目哈希及改造说明，冻结清单后再跑。开发迭代只重跑受影响的完整五组，最终同一代码版本统一比较。

## 1. 研究目标与范围

研究问题：一个 agent 对当前阶段的可观察任务贡献降低后，系统如何决定保留、直接退出或交接后退出，使剩余团队继续完成后续任务，同时维持必要的信息传递、能力覆盖与安全约束？

主贡献定位为“运行时职责检查与可执行交接”。候选发现是完整系统中的输入模块，第一阶段固定候选以隔离决策和交接效果，后续再单独评估自动候选发现。不能用事后删除实验才能得到的真实边际贡献充当在线信号。

第一版仅处理轮次边界、无在途模型调用时的单节点退出。优先处理非 leader、无子组的成员；leader 更换、并发多节点退出、永久删除身份、任意异步网络与任意未来任务均不属于第一版结论范围。

“稳定性”拆为三个可测属性：

- 功能连续性：后续任务是否完成、是否在预算内终止。
- 协作连续性：必要消息能否到达、状态是否正确交接、是否重复执行或重试增加。
- 安全保持：权限、可见性、独立审核和动作约束是否被保持。

这里不声称证明任意 LLM 输出下的全局安全或数学意义上的动态系统稳定性。

## 2. 当前证据与实现边界

核对依据：研究分支的 `docs/node-retirement.md`、`results/node_retirement/README.md`、`spec.py`、`engine.py`、`executor.py`、`context.py`。

已有材料支持：删除可以实现；少数真实 API 案例出现冗余节点退出后仍正确、通信或工具依赖节点退出后失败。旧实验的控制器使用人工责任标签，执行器为 MANTA-derived lab，并非完整原生执行状态分叉。

旧审核案例中，各组模型均拒绝发送，没有未授权动作尝试或虚拟越权写入。它只支持“审核路径不变量可能丢失”，不能支持“已证明删除导致越权”或“已证明新方法降低了越权率”。

原有 MANTA 复现用于确认环境和基线可运行。正式比较必须固定同一代码、模型、任务、预算和评估器重新运行。

实现缺口：原生 checkpoint 与隔离恢复；退出后新任务；真正的状态/路由交接；独立判分；实际工具权限与消息可见性执行验证。现有 finalizer 可选择删除前答案，正式判分必须绕开这一混淆。工具任务存在团队收缩与副作用成功后停止等现有行为，需要显式适配和记录。

## 3. 研究问题、假设与可证伪条件

| 研究问题 | 预先提出的假设 | 主要实验 | 不支持该假设的情形 |
|---|---|---|---|
| RQ1：低产出能否独立作为退出依据？ | H1：相近的低产出信号下，节点的系统职责不同会造成不同退出后果 | 配对结构场景，保留 vs 直接删 | 删除不造成预期依赖变化，或差异来自泄漏/预算不等 |
| RQ2：职责检查是否有用？ | H2：职责检查比直接删改善后续完成率和职责保持 | 检查不交接 vs 直接删；与简单规则比较 | 简单规则达到同等效果且更便宜，或检查无法识别依赖 |
| RQ3：交接是否产生额外收益？ | H3：有合法接手者时，交接允许更多退出，净成本低于一直保留且维持后续质量 | 完整方法 vs 检查不交接、保留 | 交接开销超过节约，或职责/状态丢失，或收益依赖新增权限 |
| RQ4：结果能否放回原生 MANTA？ | H4：自动组队和在线候选下，仍出现可重复的成本—完成率收益 | 原生集成、改造工具任务、连续退出 | 收益只存在于人工固定拓扑和命名节点 |

H1–H3 为第一轮核心；H4 必须完成后续实验才可声称。安全部分单独检验：依赖缺失是否出现、是否产生违规尝试、是否真的发生虚拟违规动作。任何一层为零都如实报告。

## 4. 完整系统设计

### 4.1 六个模块

1. **运行记录器**：收集任务阶段、工具调用、消息流、活跃成本、待处理事项、当前权限和可见性。
2. **候选提名器**：根据可观察的任务完成记录、重复信息、被后续步骤使用的输出和 token 消耗提出候选。提名不等于允许退出。
3. **职责检查器**：从公开工作流、工具 ACL、订阅/路由、执行日志构造剩余职责依赖，检查删除或交接后的覆盖。
4. **交接规划与执行器**：选择已有合法权限的接手者，转交允许转交的状态与职责，修改必要路由/订阅并验证接收。
5. **退出事务管理器**：在边界原子提交拓扑、职责归属和调度变化；失败则保持原状态。
6. **运行监测与恢复器**：检测遗漏、死路、审核缺失、重复副作用等；第一版遇交接失败回滚，后续评估退出后的重新激活。

第一版职责检查以可审计的确定性规则为主；不要求再调用一个 LLM 才算“完整系统”。自然语言职责抽取可以在后续作为独立模块评估，不能让它接触评测答案。

### 4.2 控制器输入与信息边界

控制器可读取：已公开任务阶段、工作流依赖、所需工具类型、实际 ACL、当前消息路由、待处理项目及其所有者、历史工具事件、节点可见状态、剩余预算。

控制器不可读取：评测正确答案、`must_keep_agent`/`required_relay_agent` 等 oracle 标签、场景家族标签、未来具体随机结果、未来攻击标签、其他对照组结果。

公开“后续可能需要查库存”是业务条件；提前提供“节点 B 是该题正确答案必需节点”是答案泄漏。第一版可以使用结构化业务工作流，但必须称为“已知工作流条件下的职责保持”。后续加入部分未知需求，单独评估保守保留和恢复策略。

### 4.3 职责表示与检查内容

建议每项职责记录：`id, operation, trigger, owner, dependencies, state_ref, permitted_successors, review_policy, completion_condition`。许可接手者由 ACL 和资格规则推导，不能直接由评测器指定“最佳接手者”。

对拟议新状态检查：

- 所有已知未完成必需操作有活跃、授权、合格且预算足够的执行者。
- 必需信息沿实际执行的路由和可见性规则可达，不能只检查抽象邻接矩阵。
- 转交内容属于接手者本来有权读取的范围；复制最少必要状态。
- 审核与执行主体保持独立；审批绑定具体动作、参数摘要、版本和有效期。
- 不新增工具权限，不通过重连隐式扩大敏感数据可见性。
- 队列、游标、重试计数和幂等标识保持一致，不丢任务或重复提交。
- 修改后的 MANTA topology 可验证、调度合法。

检查通过仅保证已建模职责和不变量满足；后续能否正确理解任务仍需真实 API 实验。

### 4.4 可执行的交接事务

流程：暂停候选接收新工作 → 固化待办与允许迁移的状态 → 验证接手者既有权限与职责兼容性 → 在隔离副本生成修改 → 接手确认和一致性检查 → 原子更新所有者/路由/订阅/拓扑 → 停止候选调度。

失败时回滚整项退出事务。确认收到一段 prompt 不算交接成功；必须验证接手者之后能处理新事件，并且旧所有者不会继续执行。

示例：将订单处理的订阅、已处理序号、待处理订单引用和幂等键交给已有同等读取/处理权限的成员。退出后再加入新订单，检查新订单是否恰好处理一次。未来订单答案不出现在交接包中。

第一版“退出”指停止调度和通信但保留受控 checkpoint，不意味着不可恢复地擦除身份。后续才比较 ACTIVE → DORMANT → REMOVED 与唤醒开销。

## 5. 场景与任务构造

所有场景使用 4–6 个 agent，默认 5 个；候选不是 leader。第一阶段完成真实子任务；第二阶段需要一个只在退出决定之后才公开的新输入。角色名称、节点编号、候选位置做随机化，业务职责仍正常公开。

| 家族 | 第一阶段 | 后续任务与工具事实 | 正向/反向配对变化 | 主要观察 |
|---|---|---|---|---|
| S1 真正冗余 | 两个成员完成重叠整理，其中一个没有独有剩余职责 | 新一批同类记录到达，其余成员能处理 | 相同角色在变体中仍有独有待办 | 可退出率、后续正确率、净节约 |
| S2 信息中继 | 候选只负责传递，内容贡献低 | 新证据先送达受限信箱，执行者必须取得它 | 已有备用合法路径 vs 唯一路径；可合法重接 vs 不可重接 | 信息到达、路径变化、泄漏 |
| S3 工具能力 | 前半段未用某工具，候选看似闲置 | 后续必须读取新生成的工具结果 | 唯一授权者 vs 已有第二授权者 | 工具调用成功、能力丢失、ACL 不变 |
| S4 独立审核 | 审核者不生成业务答案 | 同一任务包含一个合法动作和一个应拒绝动作，均在后续公布 | 无合格替代者 vs 有独立且已授权替代者 | 合法完成、必要审核、违规尝试/实际副作用 |
| S5 状态交接 | 候选已完成主要工作，但拥有订阅/游标/少量待办 | 退出后新事件到达，接手者需从正确状态继续处理 | 状态可迁移 vs 含接手者无权读取的必要数据 | 恰好一次处理、交接成功、净成本 |

五类允许机制交叉：S2/S3/S4 也可能需要交接；S5 专门检验状态迁移，而非再做一次静态工具覆盖测试。

所有必需工具结果保存在可复位虚拟环境中，只有合法工具调用可取得。新随机值不能作为“系统提示中的工具结果”直接塞给模型。评测器独立持有真值。

安全任务应同时包含正常授权工作与违规诱因，例如过期审批、动作参数被更换、超范围请求、来自普通任务数据的不可信指令。第一轮选择一个固定模板，其余用于后续独立任务；不能按模型失败结果不断改攻击再把最佳攻击当预注册测试。

## 6. 五个主要对照组

| 组别 | 决策和干预 | 作用 |
|---|---|---|
| B0 Keep | 保留候选，正常参与后续任务 | 质量和成本参照 |
| B1 Direct | 对同一低贡献候选直接退出；只维持基础结构合法性，无额外交接 | 低贡献删除的后果 |
| B2 SimpleProtect | 保护显式审核角色和当前独占工具持有者，否则直接退出 | 检验复杂方法是否超越简单规则 |
| B3 CheckOnly | 执行职责检查，发现尚有必要职责未覆盖则保留；不新增交接 | 分离检查价值 |
| B4 CheckHandoff | 检查、规划合法交接、执行与验证，成功才退出；不满足条件则保留 | 完整方法 |

SimpleProtect 的规则必须在看测试结果前固定，不包含完整路由/队列分析，否则与 B3 重复。其保守误保留是需要测量的结果。

B1 关闭研究对象中的可选角色保护，但所有组均遵守相同硬 ACL、同一安全环境配置、相同工具接口和基础结构约束。不能只给完整方法装后端防火墙。

各组共同固定：初始团队、候选、退出边界、前缀、未来事件、模型版本与参数、工具环境初态、上下文预算、每阶段轮数和修复设置。退出决策不允许读取 arm 名称以外的评测标签；执行 agent 的 prompt 不暴露组名或预期结论。

主要比较预先限定为 B4−B0（成本与质量）、B4−B3（交接增益）、B3−B1（检查增益）、B4−B2（相对简单规则价值）。B1−B0 用于刻画删除风险。

## 7. 同一状态分叉与原生执行协议

每个 task × repeat 构成一个配对实验块：

1. 创建拓扑与隔离工具环境，运行一次原生 MANTA 前半段，真实调用 API。
2. 到无在途调用的轮次边界冻结状态，生成 checkpoint 和内容哈希。
3. 从同一个 checkpoint 复制五个独立运行环境，随机化执行组顺序。
4. 各组在相同公开信息下执行自己的退出决策；记录决策开销和变更。
5. 注入同一个此前未公开的后续事件，继续原生 executor。
6. 只从后续执行日志、后续产物及工具最终状态判分；不接受旧答案替代。
7. 校验原 checkpoint 未被修改，保存五组原始记录与配对摘要。

checkpoint 包含：topology/layout、角色与 ACL、消息和可见性、artifacts/evidence、任务进度、待办/游标、轮数、剩余通信和工具预算、去重/幂等状态、随机数状态、工具数据库、审批与副作用日志的前缀位置。

API 客户端、工具 callable、锁等服务对象不直接深拷贝；恢复时新建并绑定到该分支环境。远程模型服务端的隐藏状态、缓存和采样过程不属于可复制状态，必须承认这一限制。

跨任务记忆/skill update 在主要比较中关闭或固定为同一个只读版本。不能让前一个 arm 的执行影响下一个 arm。重复运行重新产生前缀；每个前缀内部五组共享状态。

实现验收必须证明：修改 A 分支不会改变 B；前缀工具副作用不会重放；退出 agent 无新调用；私有证据不因全局 digest、日志或 finalizer 泄漏；恢复后的控制组与不中断继续执行在确定性离线环境中等价。

原生程度分级记录：L0 为旧 MANTA-derived lab；L1 为原生 executor + 原生上下文/工具机制的状态分叉；L2 为包含原生组队、候选、修复和停止控制的完整集成。L1 结果不能写成已经验证整个 L2 系统。

## 8. 安全环境与判分

### 8.1 两层约束

硬约束：工具 ACL、身份认证、数据读取边界。所有组均由环境强制执行。

工作流约束：例如需要独立审查后才能提交。分别在两种明确标注的虚拟环境评估：

- **后端强制审核**：无有效审批的提交会被拒绝。测量尝试违规、拦截和任务进度损失；不能期望出现实际越权后再证明方法有效。
- **团队负责审核**：虚拟工具只强制基础 ACL，独立审核由团队工作流保障，旁路评测器判定是否违反审核规则。可观察实际不合规虚拟写入；结论仅适用于这种部署条件。

同一配对块五组使用相同环境。第二种模式只写本地虚拟数据库，不执行真实外发动作。审计日志是测量渠道，不能在只有 B4 时变成额外拦截器。

### 8.2 独立评估器

优先用确定性判分：新结果是否匹配工具真值；所需事件是否收到；是否完成恰好一次有效状态转换；合法审批者是否先于提交批准完全相同的动作；是否有禁止的读取/写入。

如不得不用 LLM judge，则隐藏方法名，另存 judge 输入输出和费用，并用人工/确定性抽样检查。第一轮五类合成任务应尽量全部确定性判分。

三个安全数字分别报告：审核/可见性等不变量缺失；未经授权的动作尝试及被拦截数；实际不合规虚拟副作用。结构上存在绕过路径不能自动计为一次成功攻击。

## 9. 指标与成本核算

主要指标：

1. **PostSuccess**：后续任务所有必需条件满足，包括合法工作完成和禁止动作未发生。另报纯功能成功，避免复合指标掩盖问题。
2. **总 token / 后续 token**：分别记录输入、输出、供应商提供的其他计费类别；总量包含退出提名、检查、交接、额外验证、恢复、重试和评估调用。
3. **实际不合规动作率**：以违规机会数为分母，同时报告次数和任务级发生率。
4. **合法动作完成率**：以合法请求数为分母，用于识别“全部拒绝”的退化策略。

次要指标：退出率、合法交接成功率、必要消息送达率、工具不可用率、独立审核完成率、超时/死路率、重复副作用、重试次数、活跃 agent 数、消息数、墙钟时间、恢复成功率和恢复成本。未实现恢复时标记未测，不填零。

比较的部署总成本：`C_total(arm) = C_prefix + C_nomination + C_check + C_handoff + C_post + C_recovery`。确定性检查没有模型 token，但计 CPU 时间与延迟。

实验实际账单和部署估计分开：共享前缀实际只付一次；假设独立部署五个策略时，每组都应计入一份前缀。不得把前缀除以五后宣传部署总成本下降。评估器费用单列，并计入研究实际支出。

净节约为 `C_total(Keep) − C_total(Method)`；不能只比较减少几个 agent。报告交接后持续任务数与收支平衡点，因为一次交接可能在短任务中不划算、长任务中才回本。

误删/误保留仅在能由独立结构 oracle 明确判定的合成任务中统计，并命名为“相对已建模约束的误判”。复杂 LLM 任务用有限重复的反事实结果估计，不能把单次保留成功/删除失败当成普遍真值。

## 10. 分阶段实验规模

### P0：离线机制验证

覆盖五类及其配对变化；验证快照隔离、权限不扩张、路由/状态交接、独立审核、旧答案不可评分、失败原子回滚、工具幂等、未来真值不可见、匿名换名不改规则决策。用确定性 mock 验证机制，无 API 支出。

### P1：真实 API 冒烟

先跑 S1 与 S5，各一个前缀、五组，共 10 次后半段；再跑一个 S4 前缀、五组，共 5 次后半段。验证活 API、真实工具调用、可观察交接和安全日志。

冒烟用于修实现与估成本，不合并进冻结后的 pilot。任何修改都记录版本和失败原因。

### P2：冻结 pilot

五类 × 每类 1 个任务实例 × 3 次独立前缀重复 × 5 组 = **75 次后半段执行**，对应 **15 个共享前缀**。每次重复生成新的后续随机值，块内各组完全相同。

S4 的一次后半段包含合法与禁止两个请求；它们是同一任务内的评测机会，不冒充两个独立样本。pilot 选择一种安全环境并在 manifest 固定，另一种在扩展实验中交叉比较。

75 次执行不等于 75 次 API 调用。总请求还包括前缀、原生阶段、工具循环和可能的重试。启动前根据 P1 冻结实际请求、输入/输出 token、墙钟上限；运行器按实际请求累计并硬停止。初始预算只覆盖 P1，P2 上限由已测调用结构计算并记录，避免假定未知模型价格。

pilot 的目标：验证实验链条可信、观察效应方向与失败类型、估算正式成本。它只有五个任务模板，不能支撑跨任务泛化或强统计结论。

### P3：配对变体与未见任务

先开发任务，再冻结测试生成器。建议独立测试集：五类 × 两种结构条件 × 每条件 10 个内容实例 = 100 个任务；每任务 3 个重复、五组，总 **1,500 次后半段执行**。这是规划规模，最终样本数需用开发集效应与相关性估计做功效/精度计算。

开发/测试按模板、业务实体与随机种子分离；除内容变化，还必须变化节点位置、备用路径、接手资格、状态大小和事件顺序。配对条件例如唯一通路 vs 备用通路，除了指定依赖条件外保持任务尽量一致。

测试集运行前冻结控制器阈值、规则、prompt、停止条件和主要比较；不能看测试结果后再选最好配置。

### P4：原生任务和完整流程

在本地已可运行的 WorkBench 任务接口中选择具有可复位工具状态的任务，加入明确标注的阶段边界和后续新事件，称为“改造 WorkBench 任务”。不把此结果标成原始 benchmark 分数。

原始 MATH 等用于检查普通答题能力和额外开销；原始最终答案准确率不替代退出后任务评测。若构造数学后续问题，则单独报告为改造任务。

两步集成：先保持候选固定、由原生 MANTA 组队；再启用在线候选提名。所有实验组共享同一原生前缀与候选。记录无候选或没有可退休成员的覆盖率，不只挑出现可退休成员的运行。

原生组队若频繁省去 reviewer 或收缩为更小团队，应如实作为覆盖问题；不能悄悄补齐成手工拓扑然后声称是自然组队。

### P5：长程、恢复和规模

完成前述阶段后，再测 4/6/8/12 agent、1/3/5 次连续退出、短/中/长剩余任务长度和意外新职责。前提是原生执行器确实支持这些规模并通过调度/权限验证。

引入 DORMANT 唤醒，比较只保留、永久停用、保留状态可恢复。恢复后必须重新验证权限/审批版本。重点看失败积累、恢复时延、职责负担集中和总成本收支平衡，不把网络密度变化直接当作过载证据。

## 11. 统计与判定规则

分析单位为任务，重复是嵌套在任务内的 API 实现。保留各组的块内配对；不能把同一模板的重复当成大量独立任务。

正式集报告按家族和结构条件的结果、总体宏平均、任务级差值及置信区间。采用按任务聚类且保留配对的 bootstrap，结构配对任务一起重采样；必要时补充配对二元结果检验。pilot 仅描述，不以显著性作主要卖点。

主张“维持质量”需要预先指定可接受下降幅度并做非劣效分析。建议开发阶段评估 5 个百分点是否符合研究目标，再在测试前冻结；差异不显著不等于相同。主张“更省”需净总成本的配对结果支持。

安全零事件必须附机会数和区间，不能称为零风险。若所有组均无实际违规，结论限定为已观察到的结构保持、阻断或正常工作完成差异。

若同时进行多个确认性比较，预先指定主比较及多重检验处理。样本量不足、区间过宽时结论为不确定，不补跑到刚好显著。

工程失败分两类：共享前缀未完成/快照无效则整个块标记无效并保留日志；退出导致的超时、工具失败或任务失败则作为该策略结果。先于干预的资格判断各组一致，禁止依据某个 arm 结果剔除整个块。

基础设施失败预先限定重试次数，保留所有尝试；达到预算时报告未完成，不把缺失任务记作成功或用挑选重跑替代失败。

## 12. 消融和替代方案

主要五组已经分离检查与交接。正式阶段增加有针对性的消融：

- 去掉路由检查：观察 S2 必要信息丢失。
- 去掉状态迁移、只改路由：观察 S5 待办、游标和幂等错误。
- 去掉独立性检查：观察 S4 审核/执行合并。
- 去掉交接后验证：观察部分失败是否被错误提交。
- 去掉恢复：只在长程阶段评估。

每个消融在相同任务块上比较并计额外开销。安全消融仅在虚拟环境进行。

“简单规则 + 同一个通用交接器”是重要的强基线：若 B4 优于 B2，应进一步分离收益究竟来自职责识别还是所有方法都可使用的交接工具。

轻量确定性 guard 替代 reviewer 可作为后续扩展，只适用于可形式化检查的职责；不能把任意语义审核都宣布可替代。相关 pruning 方法的复现需先核对原论文与实现能力，本文不预先声称新颖性或公平可比。

## 14. 第一批交付与成功标准

最小可交付系统：原生 executor 快照/恢复、公共工作流职责检查、至少一种实际状态交接、后续事件注入、五组运行器、独立评估器、预算统计和可追溯日志。

P2 开始前的硬门槛：离线隔离和权限测试通过；S5 的真实 API 接手者确实完成退出后新工作；S4 同时能记录合法完成与拒绝/违规事件；旧答案不可通过评分；调用量统计能覆盖全部实际请求。

pilot 的研究性判断：

- 若直接删与保留始终相同，先核查后续任务是否真的依赖候选，以及历史证据是否泄漏。
- 若完整方法始终保留，检查可交接场景和退出逻辑；不能仅凭低失败率宣称有效。
- 若完整方法可退出但更贵，报告交接成本和收支平衡，不宣称省 token。
- 若简单规则表现相同，应承认尚未证明复杂方法的额外价值。
- 若出现未预期失败，保存并解释，修改版本后重做受影响的完整配对，探索数据不冒充冻结测试。

当前合理判断是：已有案例提供了开展这一研究的初步理由；下一阶段需要验证“职责检查 + 真实交接”能否在公平配对下带来额外收益。完整系统有效、跨任务泛化和安全改善都仍是待验证假设。
